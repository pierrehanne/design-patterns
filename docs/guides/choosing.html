Adapter, Decorator, Proxy, or Facade?

All can wrap another object, so structure alone does not identify intent. Adapter translates a contract. Decorator adds behavior while keeping the component contract. Proxy controls access to a service. Facade offers a simpler use-case interface over several operations. One object can serve more than one role, but naming each policy separately often makes composition easier to test.

For a weather integration, an adapter translates the provider payload, a proxy caches results, a decorator measures latency, and a facade combines weather with travel planning. Write the order down: measuring outside the cache reports client latency, while measuring inside reports provider latency.

Strategy, State, or Template Method?

Ask who chooses the behavior and why. Strategy is chosen as an alternative algorithm. State follows an object’s lifecycle and valid transitions. Template Method fixes a sequence while allowing selected steps to vary. A context holding an interface could implement any of these; the reason for switching determines which explanation fits.

For document processing, an export format can be a strategy, publication status can be a state, and a fixed read-parse-analyze workflow can be a template method. Keep these decisions distinct unless they truly change together.

Command or Memento?

Command stores an action and possibly an inverse; Memento stores a snapshot. A short edit on a large document may make command history economical, but an irreversible local transformation may be easier to undo from a snapshot. A hybrid command can capture a memento before execution.

Neither guarantees correct undo after unrelated concurrent edits. Identify the version of the receiver the history applies to. For external side effects, use explicit compensating actions with their own failure states.

Visitor or ordinary polymorphism?

Draw a matrix of element types against operations. Visitor favors adding a new operation as a column: one new visitor covers existing elements. Adding a type creates a new row that every visitor must handle. Ordinary methods often make adding types easier but distribute a new operation across those types. Choose the direction of change your system actually experiences.
